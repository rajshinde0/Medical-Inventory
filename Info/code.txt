-------------

  5. During login, user looked up by ID
  6. Password verified
  7. User data stored in Flask session

  Example: d003,Dr. Kumar,Doctor,doc789
  
  Auto-ID Generation:
    - Find highest existing number for role
    - Increment by 1
    - Format with leading zeros (001, 002, etc.)

│              │ ──> Writes ──> history.txt (logs operations)
└──────────────┘


DATA SYNCHRONIZATION:
--------------------
Both applications (C++ and Flask) share the SAME data files:
  ✓ Changes in C++ app → Reflected in Flask app
  ✓ Changes in Flask app → Reflected in C++ app
  ✓ Real-time data sharing through file system


STARTUP SEQUENCE:
----------------
1. Application starts
2. Load users from users.txt → Create User objects
3. Display login prompt
4. User enters credentials
5. Validate against users.txt
6. If valid, create user session
7. Load inventory from inventory.txt → Create Medicine objects
8. Display menu
9. User performs operations
10. Each operation logs to history.txt
11. Login/logout logs to user_history.txt
12. Changes save back to inventory.txt
13. Cycle continues until logout


FILE MODIFICATION FLOW:
-----------------------

Add Medicine:
  1. User enters medicine details
  2. Create new Medicine object
  3. Add to inventory collection
  4. Write entire collection to inventory.txt
  5. Log to history.txt: "Added medicine: [details]"

Update Medicine:
  1. Load inventory from inventory.txt
  2. Find medicine by batch number
  3. Modify Medicine object
  4. Write entire collection back to inventory.txt
  5. Log to history.txt: "Updated medicine: [details]"

Sell Medicine:
  1. Load inventory from inventory.txt
  2. Find medicine by batch
  3. Reduce quantity
  4. Write collection back to inventory.txt
  5. Log to history.txt: "Sold [qty] of [medicine]"


ERROR HANDLING:
--------------
Missing users.txt:
  → Create default users
  → Write to users.txt
  → Continue execution

Missing inventory.txt:
  → Start with empty inventory
  → User can add medicines
  → Creates file on first save

Missing history.txt:
  → Created on first write
  → Append mode always
